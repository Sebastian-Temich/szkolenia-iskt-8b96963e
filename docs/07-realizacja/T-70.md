# Raport T-70: Build na Vercel bez konfiguracji Lovable

Issue: #70
PR: #73

## Co zrobiono

- **W-18: `pnpm build` tworzy wyjście Vercel bez Lovable.** `vite.config.ts` z `defineConfig` z
  `vite`: `tanstackStart` (`server.entry: "server"`, ochrona importów `**/server/**` i `server-only`
  jak w wrapperze), `nitro` (preset `vercel`, `vercel.functions.regions: ["fra1"]`, tylko przy
  `command === "build"`), `@vitejs/plugin-react`, `@tailwindcss/vite`, `resolve.tsconfigPaths: true`,
  alias `@`, wtyczka naprawy komentarza bez zmian, devtools (`@tanstack/devtools-vite`) tylko przy
  `mode === "development"`. Z `package.json` i `pnpm-lock.yaml` usunięte
  `@lovable.dev/vite-tanstack-config` i `vite-tsconfig-paths` (`grep -c -E "lovable|vite-tsconfig-paths"
  pnpm-lock.yaml` → 0); dodane jawnie `@tanstack/devtools-vite` 0.8.6 (ta sama wersja, która była
  przechodnia w lockfile). Lockfile zmienił się tylko o te paczki i ich zależności (`globrex`,
  `tsconfck`). Wynik builda: `.vercel/output/{config.json,nitro.json,static,functions/__server.func}`,
  `.vc-config.json` funkcji: `"regions": ["fra1"]`, `"runtime": "nodejs24.x"`, `launcherType: Nodejs`.
- **`pnpm dev` na 8080, lint, typy, testy.** `server: { host: "::", port: 8080 }` jak w wrapperze;
  `pnpm lint` (0 błędów), `pnpm typecheck`, `pnpm test` zielone. Uruchomienia `pnpm dev` nie sprawdziłem
  lokalnie (sandbox blokuje porty); dowód: job CI `e2e` (run 43976076726, zielony), w którym
  Playwright sam startuje `pnpm dev` na `http://localhost:8080`.
- **W-19 / O-37b: test serwera.** `src/test/zgloszenia-serwer.test.ts`, dwa testy w „W-12/K5: limit
  zgłoszeń”: „ZGLOSZENIA_NAGLOWEK_IP=x-vercel-forwarded-for: adres z nagłówka Vercel, nie z
  x-forwarded-for” (przez `czytajKonfiguracje` i `adresKlienta`) oraz „przy x-vercel-forwarded-for
  zmieniany x-forwarded-for nie zeruje limitu” (6 zgłoszeń, zmienny `x-forwarded-for` i adres gniazda,
  stały `x-vercel-forwarded-for` → `[200×5, 429]`). Kod `src/lib/zgloszenia/` bez zmian: testy
  charakteryzują istniejące zachowanie i przeszły od razu.
- **Wtyczka naprawy komentarza i dokumentacja.** `src/styles.css` bez zmian (`git diff origin/main --
  src/styles.css` pusty), build bez błędu CSS, a wynikowy CSS zawiera blok `.dark` leżący za naprawianym
  komentarzem. `AGENTS.md`: sekcja „Lovable” (build bez Lovable, synchronizacja do odłączenia przez
  właściciela, ADR-006) i wiersz „Build” w „Stack”; `README.md`: sekcja „Build”, port 8080 w
  uruchomieniu, zakres M5.

## Decyzje

- Które zachowania wrappera Lovable odtworzyć? → Te, których aplikacja potrzebuje albo które wpływają
  na wynik: `importProtection`, wstrzyknięcie `VITE_*` przez `define` (`loadEnv(mode, cwd, "VITE_")`),
  `dedupe` React/TanStack Query, `optimizeDeps.include`, `css.transformer: "lightningcss"` (ten sam
  parser CSS co dotąd; `lightningcss` jest zależnością `vite`), port 8080, nitro tylko w buildzie.
  Pominięte: diagnostyka błędów SSR i funkcji serwerowych dla nakładki Lovable, proxy zasobów podglądu,
  bramka HMR, opóźnienie obserwatora plików i dokumenty prerenderu: działały tylko w piaskownicy Lovable.
- Wersja `@tanstack/devtools-vite`? → 0.8.6 dokładnie, tak jak w lockfile (zależność wrappera).
- `minimumReleaseAgeExclude` w `pnpm-workspace.yaml` (5 paczek `@lovable.dev`)? → usunięte: żadna
  paczka `@lovable.dev` nie jest już zależnością, a wyjątek tylko osłabiał ochronę łańcucha dostaw.
- `.gitignore`: dopisany `.vercel` (wyjście builda).
- `playwright.config.ts`: zmieniony tylko komentarz o źródle portu 8080.
- Lokalny build mimo `EPERM` na `.env.local` → czysty klon gałęzi w scratchpadzie sesji (bez
  `.env.local`), bez obchodzenia blokady odczytu pliku.

## Drobne uwagi

- `pnpm peers check`: niespełniona zależność równorzędna `ocache >=0.3.0` dla `h3@2.0.8` (zainstalowane
  0.1.5); pochodzi z nitro, nie z tej zmiany.
- `vitest.config.ts` używa `__dirname` (ostrzeżenie Vite o `configLoader: 'native'`); poza zakresem.

## Ryzyka

- Wdrożenia na Vercel nie sprawdziłem (projekt Vercel zakłada właściciel, T15). Sprawdzone tylko
  wyjście builda w formacie Build Output API.
- Adres klienta na Vercel: `getRequestIP()` w funkcji Vercel to adres proxy platformy, więc limit działa
  poprawnie tylko z `ZGLOSZENIA_NAGLOWEK_IP=x-vercel-forwarded-for` w zmiennych projektu (ADR-006 pkt 4,
  zadanie właściciela).
- Lovable nie zbuduje projektu po merge'u (brak wrappera). Dopóki synchronizacja działa, publikacja z
  Lovable byłaby zepsuta; zgodnie z ADR-006 właściciel odłącza Lovable.
- `pnpm build` w worktree workera nie działa, dopóki leży tam `.env.local` (wtyczka nitro zawsze czyta
  `.env` i `.env.local`, a sandbox zabrania odczytu). CI (bez `.env.local`) buduje normalnie.

## Propozycje dla systemu

- Profil workera: `pnpm build` w projektach z nitro pada na `EPERM` przy `.env.local` dodanym przez
  `shctl task dispatch`. Propozycja: opisać w `sh-stack-*` obejście z czystym klonem w `$TMPDIR` albo
  dodać do shctl komendę „build bez env” (klon gałęzi i build).
